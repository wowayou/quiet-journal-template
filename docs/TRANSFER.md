# 内容导入、导出与迁移

本轮提供**本地内容快照工具**，不是万能格式转换器，也不是手机上一键改整个仓库的后台。实现位于 `scripts/content-transfer.mjs`，只使用 Node.js 内置模块和既有媒体检查，无新依赖、网络请求、自动 Git 提交或云端任务。需要 Node.js 18+。

## 先分清要做哪类迁移

| 需求 | 本轮支持方式 | 不包含什么 |
|---|---|---|
| 把本站当前文章、图片和内容设置带走 | 导出带清单的普通目录，校验后原样导入新隔离目录 | 已删除版本、未保存的浏览器草稿、完整 Git 历史 |
| 两个 Quiet Journal 站点之间搬内容 | 只读比较新增/相同/冲突，再在有备份的分支上人工合并 | 不自动覆盖同名文章或站点设置，不删除目标独有内容 |
| 本地编辑器与 CMS 之间切换 | 保持相同 Markdown、图片路径和 YAML 契约 | 非标准 Markdown 插件和短代码不会自动转换成别的平台语法 |
| WordPress、Notion、其他博客系统导入 | 暂不实现通用转换；先提供真实导出样本，再确定字段、图片和旧 URL 映射 | 不抓整站、不下载外链图片、不猜原始发布时间和公开状态 |
| 换域名、Git 仓库、托管平台或 R2 | 按部署/更新/媒体迁移文档分别规划、授权和验收 | 工具不修改 DNS、令牌、远端、历史、账单或自动部署 |

这是有意选择的边界：一次批量导入可能同时造成泄露、覆盖和数百次构建。先得到可检查、可丢弃的本地结果，比在手机界面里做一套额外的认证和批量写入系统更稳妥。后台顶栏「导入 / 导出」提供本地操作说明，不会读取令牌或导出私有仓库。

## 导出的范围

保留**文件原始字节和路径**，包括 UTF-8、换行、front matter（文首元数据）、原有草稿/公开标记及图片引用，不重新起 ID：

- `content/**` 中的 `.md` 和 JPEG/PNG/WebP，包括普通页面、文章和未引用的随文图片。
- `assets/media/**` 中的 JPEG/PNG/WebP，包括共享图、图标等。
- `data/site.yaml`、`data/links.yaml`、`data/widgets.yaml`、`data/answers.yaml`（存在时）。

**不包含** `.git`、`.env`、CMS 配置/令牌、Worker 与域名配置、主题和扩展代码、许可证目录、构建产物、缓存、其他任意 data 文件。`data/comments.yaml` 与独立面板/服务的配置、`.env.local`、Vercel 项目关联和数据库归档也不包含；文章里的 `comments` 标记仍按原字节保留。外部 Waline 数据库/评论需独立备份，已提供 [手动备份与空库恢复流程](../integrations/waline-server/README.md#独立手动备份与恢复)，不混入内容包。模板更新和完整恢复另见 [UPDATING.md](UPDATING.md)、[EDITING.md](EDITING.md#删除与恢复)。

它不是面向公开分享的导出：草稿、未来文章、未引用图片及联系方式都会包含。工具不能识别你写在正文/设置里的密码、人物或地点；文件去元数据也不等于画面没有私人信息。**写操作必须显式添加 `--include-private`，但这个开关不是脱敏或加密。**

## 三步操作

先在 CMS 保存工作，在电脑上同步最新远端，并停止同时编辑。不要先执行 `reset --hard` 或覆盖未提交文件。

### 1. 导出

在本地博客仓库根目录运行：

```sh
npm run content:export -- --output ../journal-content --include-private
```

得到普通目录：

```text
journal-content/
├── manifest.json
└── files/
    ├── content/...
    ├── assets/media/...
    └── data/...
```

`manifest.json` 记录格式 `quiet-journal-content`、版本 `1`、创建时间、私有内容声明，以及每个文件的路径、字节数和 SHA-256（文件完整性校验值）。清单最后写入；导出前后会复查源文件，发现编辑期间变化则失败。

输出的父目录须已存在，目标必须全新，**已有空目录也不覆盖**。工具拒绝输出到源目录或识别出的 Git/Hugo 工作区内，尤其不要放到 `static/`、`public/`、`content/`。它无法发现每一种自定义 Web 服务器发布目录；你仍须选择私人存储位置。

在支持 POSIX 权限的系统上，新目录仅所有者可读写进入，文件仅所有者可读写；不是加密。可以自行压缩/加密整个目录用于保管，但本工具不直接解包 ZIP，也不绕过操作系统的备份权限。

### 2. 校验与比较

```sh
npm run content:inspect -- --source ../journal-content
npm run content:inspect -- --source ../journal-content --compare .
```

第二条只读比较目标站点，报告：

- `add`：此路径可新增。
- `same`：路径和内容相同。
- `conflict`：内容不同，或存在大小写、Unicode、文件与目录冲突（包括空目录占用文件名）；不自动选择任何一方。
- `targetOnly`：目标里独有的文件数量，不会被删除。

退出码：`0` 为校验成功且无比较冲突，`2` 为发现比较冲突，`1` 为参数/校验/文件操作失败。报告不是合并操作；目录和媒体检查也不是完整的站点链接/业务校验。

### 3. 导入新隔离目录

```sh
npm run content:import -- --source ../journal-content --output ../journal-review --include-private
```

得到 `content/`、`assets/media/`、所选 `data/` 和最后写入的 `IMPORT-REPORT.json`。**不会覆盖当前工作区，也不会自动打开草稿开关。** 已发布文章的 `draft: false` 会被忠实保留，因为导入只是隔离复制，不是发布。若准备把它们加入正在使用的站点，拿不准的条目请先设为草稿。

之后的合入由你控制：

1. 为目标站点保存独立备份，在更新分支逐项比较。
2. 对同名文章、共享图片和 `data/site.yaml` 等设置人工决定；保留目标的作者信息、导航和定制，不把整个目录覆盖上去。
3. 使用**可信的目标模板代码**构建，确认页面功能、日期、草稿隔离、站内链接、图片、订阅、搜索和旧地址仍正确。工具不验证所有 front matter 语义，不执行导入目录附带的代码。
4. `npm run build` 与适用回归通过后，检查 diff，再决定提交和推送。推送 main 会使用既有云端构建额度，不要为每个导入文件单独提交。

单次操作异常会尝试清理本次创建的目标，不触碰既有目录。进程被强行终止或机器断电时，可能留下不完整目录；不要把缺少最终清单/报告的目录当作成功结果。检查后删除残留或另选新目录，不直接往残留目录续写。

## 校验与容量边界

| 项目 | 当前边界 |
|---|---|
| 文件数量 | 最多 10,000 个 |
| 单文件 | 最多 25 MiB，读取期间增长也会拒绝 |
| 总内容 | 最多 1 GiB，一次只处理一个文件，不将全包载入内存 |
| 清单 | 最多 4 MiB，拒绝未知版本/字段、无效大小或校验值 |
| 路径 | 最多 16 段、1,024 UTF-8 字节；拒绝绝对/上级/隐藏路径、反斜杠、控制符、常见系统保留名称和不可移植字符 |
| 冲突 | 拒绝包内重复、大小写/Unicode 规范化冲突、文件与目录互相占用；不默默改名 |
| 文件类型 | 拒绝符号链接、非普通文件、代码、SVG、HEIC 原图、动图、未知类型和无效 UTF-8 文本 |
| 媒体 | 复用 `check-media` 元数据/类型检查；发现 EXIF/XMP/IPTC 等就停止，不为迁移关闭检查 |
| 完整性 | 包根目录固定为清单 + files，实际文件和清单必须相符；复制时再次核对字节数及 SHA-256 |

校验值只能检查完整性，**不是可信来源签名**。会自己重算清单的攻击者也能制作格式合法的恶意内容，仍需信任来源并人工审查。媒体检查不是完整图像解码器，最终模板构建和目视检查仍然必要。不要让其他程序在操作时改写来源或目标；工具不声称是抵御同一系统用户恶意并发改写的沙箱。

超过这些边界时明确失败，不会截断文章、漏掉图片或偷偷转码。接近上限的大型媒体仓库应另行设计分批/存储迁移，不把这些数字当成站点的最终容量。

## 地址、历史与恢复

- 目录 ID、文内链接和正文中的域名都原样保留，不自动重写。**保留源路径不等于保证在另一套 permalink/页面类型配置下网址不变**。
- 当前内容导出不包含已删除文件和历史版本，不能代替完整 Git 备份；`scripts/backup.sh` 的滚动镜像也不能代替独立保留的快照。
- 更换域名或修改旧 URL 时，单独准备跳转、canonical、RSS 身份和缓存策略，见 [GROWTH.md](GROWTH.md#4-语义化链接生成器层容易迁移和长期维护需克制)。
- 转到其他编辑器可继续使用 Markdown；转到其他生成器时，`qj-link` 等 Hugo 短代码和页面布局需要转换，不能承诺无损一键迁移。
- 元数据不合格的原图应该先在本地转换、检查，再纳入内容传输；不要让一次清理替换所有历史照片。图片质量选择说明见 [EDITING.md](EDITING.md#图片压缩与质量选择)。

## 验证方式

`npm test` 包含内容传输的正向往返、私有确认、路径/符号链接/未知类型/篡改/体积/覆盖/比较冲突，以及写入中途失败清理测试。测试只使用临时合成内容，不复制作者文章。

实际使用时，先用少量非敏感内容完成导出、检查、导入和目标站构建，再做大批量操作。本轮没有自动迁移真实内容、改变远端或部署新版本。
