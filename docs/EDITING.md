# 写作与编辑器

网站不依赖任何编辑器。内容是 Markdown 和图片，设置是 YAML；Sveltia CMS（内容管理系统）只是修改这些文件的适配层。删除 `static/admin/` 后仍可构建，回归测试保留了这个检查。

## 内容约定

```text
content/posts/<稳定 ID>/index.md   文章，文件夹名决定永久链接
content/posts/<稳定 ID>/*.webp     文章图片
content/<稳定 ID>.md              普通/归档/友链/致谢页面
assets/media/*.webp               页面共用图片、上传图标，引用为 /media/文件名
data/site.yaml                    站点设置
data/links.yaml                   友链
data/widgets.yaml                 挂件配置
data/answers.yaml                 答案之书的纯文字句子
data/comments.yaml                可选评论接入（只填面板源，不写凭据）
data/editor.yaml                  实例 CMS 连接（仓库/分支/模式，不写令牌）
data/newsletter.yaml              可选邮件订阅账号与说明，默认关闭
```

```yaml
---
title: ""            # 文章可留空，取正文开头；普通页面请填标题
date: 2026-10-14T08:00:00+08:00
lastmod: ""          # 有实质更新才填；留空沿用 date
kind: note           # 仅文章：note 短记 | story 随笔 | photo 图文
summary: ""          # 列表摘要；留空取正文
description: ""      # 搜索/分享简介；不是关键词堆砌区
cover: ""            # 分享封面；留空取首图，再用全站图或生成文字卡片
cover_alt: ""
featured: false      # 首页最多 3 篇精选；已在本页“最近”里的不重复
search_exclude: false # 不进站内搜索，不代表私密
comments: true       # 仅文章：全站评论已开通时允许留言；false 不删除服务端旧评论
draft: true          # true = 不发布正文和随页图片
---
```

- 文章 ID 示例 `20261014-a7x2b9c1`。**改标题不会改链接**，改文件名/文件夹名会。不要把真名、住址放进 ID 或图片名。
- `date` 是首次发布时间，`lastmod` 是内容最后实质更新时间；不能早于发布，也不能写未来的更新时间。不要每次改错字、部署或改配色就自动刷新它。
- 输入带时区的完整时间，如 `2026-10-14T08:00:00+08:00`。可见界面只显示日期，HTML `<time datetime>`、分享元数据和结构化数据包含完整时间；RSS 按自己的日期规范输出。**不显示时分不等于源码隐藏时分**。
- 历史普通页面没有可靠时间可以留空，不编造日期。草稿、未来发布时间、已过期内容不进入正式构建。
- `noindex: true` 会建议搜索引擎不收录该页面，并从站点地图和站内搜索排除；它仍可公开访问，绝不是访问控制。文章也可在源码中设置此字段。

`/admin/config.yml` 现在由 Hugo 从 `assets/admin/schema.yml`（核心字段）与 `data/editor.yaml`（实例连接）确定性生成，JSON 为 YAML 子集。不要在 static 下保留同名副本或修改 public 产物。扩展可用 `data/editor_extensions.yaml` 追加字段/集合，重复核心 name 会失败。

## 默认工作流：保存、发布、撤下

默认 `simple` 模式，保存即提交私有仓库的 `main`。每次保存（包括草稿）会触发已有的生产构建；合并能一起改的设置，避免高频无意义保存。

1. 新建文章/页面，保持“草稿”打开，写作、上传图片、保存。
2. 发布前检查正文、链接、图片画面；关闭“草稿”再保存。**保存到 GitHub 不等于网站已上线**；查看 Cloudflare 构建及部署结果，成功后才是新版本上线。后台“发布说明”提供检查与失败兜底步骤，不读取或猜测实际云端状态。
3. 撤下前先移除其他页面/导航的引用，再打开“草稿”保存。不要用搜索排除代替撤下。
4. 网络失败先确认最后一次保存是否已提交；不要在两台设备同时编辑同一篇文章。

**后台先拦格式，构建再查关系。** 社交链接、友链、外部导航网址、自定义图标、Buttondown 用户名和评论面板源的格式与构建规则一致，填错会在字段下显示原因、不能保存。后台无法判断的跨项设置问题**只跳过出问题的那一项，网站照常更新**：导航指向的页面被删除或撤下（这条导航暂时隐藏）、挂件 ID 重复（只显示第一个）、开启订阅或评论却没填账号或面板源（入口暂不显示）。原因会出现在后台顶部的**网站状态**里。涉及隐私、安全和内容正确性的问题仍会让构建失败，网站保持上一版：原图元数据、草稿发布、不安全链接、文章引用不存在的图片或站内地址；构建日志会写明文件和字段。

**网站状态**：后台顶部按钮，显示网站当前版本的生成时间和被跳过的设置；有提示时按钮旁出现小圆点。保存后过几分钟再看，如果时间还早于你的保存，说明新版本还没上线，文章已经在仓库里。它只读本站公开的 `/build.json`，不读取 GitHub 或 Cloudflare 账户。这个文件任何人都能打开，所以提示只写“第几条导航 / 第几个挂件”，不写导航名称、页面 ID 或挂件 ID，避免透露还没公开的页面；具体名称在构建日志里。

保存后网站没更新时，先确认 GitHub 中的文章和图片、草稿开关、发布时间，再查看对应提交的 Cloudflare Builds 日志。已提交的内容不会因部署失败消失；未保存输入不能保证恢复。本站默认不用 GitHub Actions，云构建额度与保存到仓库不是一回事。云构建不可用时可由维护者在独立、最新干净克隆中完整检查后手动发布，见 [DEPLOY.md](DEPLOY.md#云构建不可用时手动本地发布兜底)；不要重复保存、删文或付费升级来催发布。

已公开过的内容可能留在阅读器、搜索引擎、第三方分享缓存和旧部署版本中。撤下只停止当前版本发布，不能追回副本。不要用真实敏感信息测试草稿隔离。

**第一次使用仍要真机验收**：自己登录 `/admin/`，写一篇不含敏感信息的草稿、上传一张图片、发布、撤下，再确认草稿和图片不能从当前站点访问。本项目原实例的 Phase 4 由作者确认完成，不代表所有用户的手机或实例都已验收。

## 新页面与页面类型

CMS 的“页面”可新建，不再局限于固定的关于页。默认文件名为 `page-<随机 ID>.md`；首次创建后保持这个 ID，即使标题改了也不改网址。旧的 `about.md` 等继续使用原来的 URL。

| `layout` | 用途 | 内容来源 |
|---|---|---|
| `page`（默认） | 关于、现在、阅读指南、其他常青页 | 页面的 Markdown |
| `archive` | 时间归档 | 页面正文 + 自动文章列表 |
| `links` | 友链 | 页面正文 + `data/links.yaml` |
| `credits` | 致谢 | 页面正文 + `data/credits.yaml` |

文章的 `kind` 只是同一文章模板的语义/显示差异，不是新增业务页面类型。需要书单、项目展示等特殊逻辑时由开发者新增布局，再配置 CMS 选项，见 [EXTENDING.md](EXTENDING.md)。导航只创建入口，不创建功能。

页面集合只管理 `content/` 根目录的 `.md`；文章集合独立管理 `content/posts/`。页面图片放 `assets/media/`。Hugo 支持额外 page bundle，但在 CMS 管理嵌套页面需要另配集合，不自动开放任意目录。

## 富文本与链接打开方式

以 Shopify 富文本编辑器的“内容操作明确、链接单独配置”为参考，但不把它的 HTML、像素级排版和嵌入代码搬过来：

- 支持可视化 / Markdown 切换、粗体、斜体、删除线、标题、引用、列表、代码、图片、表格、分隔线。
- 页面标题自动生成一级标题，正文工具栏从二级标题开始。宽表格可横向滚动。
- 图片的替代文本描述画面，标题作为图注。同段多张图并排；不要在富文本里拖成固定像素尺寸或套图片链接，模板已提供放大查看。
- 普通链接跟随全站默认：本站当前标签，外站新标签（可在站点设置改掉）。
- 单条覆盖：插入 **“链接（打开方式）”**，填写文字、地址、`auto / same / new`。组件保存下面的 Hugo shortcode（短代码），不开放原始 HTML：

```markdown
{{< link text="访问另一个站点" url="https://example.org/" target="same" title="" >}}
```

这也是不用 CMS 时的写法，可以放在段落中。CMS 会转义引号、`&` 和花括号；手写复杂参数请使用 `&quot;`、`&amp;`，不要粘贴脚本。短代码属于模板内容契约，换静态生成器时须转换成对应组件或普通链接；并非所有 Markdown 软件都能预览它。

Sveltia 原生 Markdown 链接没有保存 `target` 的语法；其 HTML 模式才有原生新标签选项。因此保留 Markdown，加一个窄小的链接组件，而不是开启任意 HTML。组件代码在 `static/admin/editor-components.js`，渲染在 `layouts/shortcodes/link.html`。

## 图片压缩与质量选择

后台顶栏的「上传质量」提供本机选择：

| 选择 | 效果 |
|---|---|
| 站点设置（默认） | 完全遵循 `config.yml`；模板的普通图片默认质量为 85 |
| 省空间 | 普通位图上传质量 75 |
| 均衡 | 普通位图上传质量 85 |
| 高质量 | 普通位图上传质量 92，不是无损或保留原图 |

数字是编码器的质量参数，不是“保留多少百分比”，也不保证固定文件大小或各浏览器编码结果一致。不同内容的收益不同；清晰文字、细节图应目视比较。

- 偏好只存在当前浏览器，不写入仓库，不触发构建，也不修改其他设备。
- **本次有效档位显示在顶栏；保存偏好在下次载入才生效。** 切换后先保存文章，再手动重新载入；工具不会自动刷新正在编辑的页面。对话框明确显示本次与下次状态。
- 通过官方 `CMS.init()` 只覆盖全局 `raster_image.quality`，不替换仓库/分支/集合，不修改 WebP 目标格式、尺寸和文件限制。模板普通图片最长边仍为 2048；字段级和格式专用规则优先，图标仍使用 512px / 质量 90。
- 已上传/已提交的图片不重压缩。网站发布时 Hugo 仍按自身的 `params.media.quality`（当前 82）生成响应式图片，分享图也有自己的设置；顶栏控制的是**入库前上传阶段**，不是所有产物的统一质量。
- 上游转换有边界：部分解码失败可能退回原文件；不能原生编码 WebP 的浏览器可能依赖按需模块或降级输出其他格式，质量参数未必同样有效。不要把选择档位当成任何输入都已安全转码的证明。构建检查也不能擦除已经提交到 Git 的元数据，换设备/格式仍需非敏感测试。

实现使用官方手动初始化和 `nc-root` 挂载点，不修改 Sveltia 内部节点；挂载区使用布局包含，让编辑页的固定层留在工具栏下方，而不是仅列表页能点到质量入口。主程序版本与 SRI 不变。`manual-init.js` 必须在主程序之前，正文组件注册与 `editor.js` 初始化保留顺序；不要只拷贝其中一个文件。浏览器存储失败会明确显示；主程序/配套脚本缺失或初始化抛错时停止进入编辑器，顶栏显示“未应用”，不自动切换 CDN，也不假装质量和正文组件已经可用。

## 邮件订阅

CMS 的“邮件订阅”只控制表单和账号，不发信。默认关闭；先自行确认 Buttondown 账号及免费范围，再填写 username。仅公开文章文末出现原生表单，提交会前往服务完成验证码/双重确认；不执行第三方脚本。实际发送频率由作者在服务端决定，不将 CMS 保存自动变成群发。评论不收邮箱、不发邮件的约定保持独立，详情见 [CUSTOMIZE.md](CUSTOMIZE.md)。

## 内容导入、导出与迁移

后台「导入 / 导出」提供本地图形向导的启动说明。在电脑同步博客仓库后运行 `npm run content:ui`，打开终端中的完整地址，即可点选导出、检查比较、隔离导入；自动生成新目录名，结果显示中文统计和保存位置。仍保留命令行工具。向导不读取 CMS 令牌、不在线拉取私有仓库、不在手机上整库写入。支持本站当前 Markdown、图片和指定内容设置；不包含历史、主题、部署配置或外部评论数据库，不覆盖既有目录，不自动发布，草稿/公开标记原样保留。

完整范围、命令、容量与隐私边界见 [TRANSFER.md](TRANSFER.md)。第三方平台转换、换域名、Git 历史迁移与 R2 迁移应分别规划，不是同一个开关。

## 可选免登录评论

本地已提供默认关闭的 Waline 接入。先在独立源部署并验收读者面板与数据/管理服务，再在“评论接入”配置隔离面板的 HTTPS 源并启用；**不是仅打开表单开关就开通服务**。只在公开文章详情显示，普通页面不自动加评论。

文章的“允许本篇留言”可单独关闭；关闭/撤下文章不会删除或锁定服务端讨论。当前不收邮箱、不发通知邮件，作者在独立 Waline 管理端审核/回复，读者主动回来查看。写作令牌不交给评论服务，评论数据库也不属于内容导出。完整操作、安全和备份边界见 [COMMENTS.md](COMMENTS.md)。

## 照片与令牌安全

- CMS 在浏览器内把照片（含支持解码的 HEIC）转成 WebP，最长边 2048，去掉 EXIF；图标字段另有 512px/2 MiB 限制。真机原图转换曾验证通过，但换设备、CMS 版本后应复测。
- 构建前 `scripts/check-media.mjs` 检查源文件，拒绝 EXIF/XMP/IPTC、HEIC、动图/视频、正文 SVG 和主动 SVG；仅共享自定义图标支持被动 SVG 白名单。Hugo 对被发布的本地位图重新编码，SVG 图标作为独立图片发布而不内联。手工上传不能绕过这些步骤。
- **原图进 Git 就留在历史里**。构建失败不会删除历史中的 GPS；尽量在提交前去元数据。画面里的门牌、人脸等仍需自己检查。
- 登录用 GitHub Fine-grained PAT（细粒度个人访问令牌），只授权自己的私有实例仓库，**Contents: Read and write**，设 30–90 天有效期。不要发给别人或写进配置。
- 只在私人设备登录。换设备先保存，丢失设备或怀疑泄露时到 GitHub 删除令牌并重新生成。令牌所在浏览器的同源脚本属于信任边界，不随便添加第三方脚本。

## 删除与恢复

Sveltia 0.235.1 已有删除二次确认，但手机列表没有桌面端的勾选/删除入口，仍需进入详情页菜单；不是配置中漏开了手势。项目目前没有回收站。暂时不想公开时，优先打开“草稿”并保存，而不是删除文件。

已提交的文章通常可以从删除前的 Git 版本恢复，随文图片也要一起核对；未提交的输入不能保证从仓库找回。恢复应在另外的干净工作区进行，按准确路径取回、先设为草稿、检查后产生新提交，不要重置整个仓库或强推旧历史。步骤和回收站取舍见 [GROWTH.md](GROWTH.md#3-删除撤下回收站与备份)。

**删除成功不等于下线成功**：其他页面仍引用它时，构建可能失败，旧线上版本会继续存在。务必检查部署结果；已公开内容在订阅器、分享缓存、历史部署和备份中的副本不会被一并追回。

## 可选审核流与升级

`data/editor.yaml` 可改为 `publish_mode: editorial_workflow`，并把草稿字段默认值改为 `false`；令牌另需 **Pull requests 读写**。保存到 `cms/*` 分支，发布时合并到 `main`，撤下仍要标草稿再发布。审核流请求更多，网络不稳定时不如 simple 直接；后台工作流不同也不能替代关闭云端预览构建，见 [DEPLOY.md](DEPLOY.md)。

CMS 版本和 SRI（Subresource Integrity，子资源完整性校验）在 `static/admin/index.html` **一起固定**。升级前读变更说明，离线/测试环境确认字段、链接组件、图片转换和保存往返，再改版本与哈希；不要只改 `@版本` 或使用 `@latest`：

```bash
V=0.235.1 # 核对后换成待测试版本
curl --fail --location "https://unpkg.com/@sveltia/cms@$V/dist/sveltia-cms.js" \
  | openssl dgst -sha384 -binary | openssl base64 -A
```

SRI 只保护主脚本，HEIC 解码等按需依赖不在其覆盖范围内。模板更新步骤与回滚见 [UPDATING.md](UPDATING.md)。

## 其他编辑方式与备份

本地编辑器（VS Code、Obsidian 等）+ Git 适合长文；GitHub 网页适合改错字，别直接上传手机原图。换其他 Git CMS 时遵守上面的文件契约，并检查上传前去元数据的行为。Sveltia [RichText 文档](https://sveltiacms.app/en/docs/fields/richtext)、[组件 API](https://sveltiacms.app/en/docs/api/editor-components)是适配层的上游依据。

`scripts/backup.sh <owner/repo>` 可在本地保存完整 Git 镜像（含历史），建议定期手工运行；没有新增计划任务。它会跟随远端更新和清理引用，**不等于不可变快照**，应另行保留带日期、不原地覆盖的快照及离线副本，防止远端历史被改写后镜像也跟着更新。备份同样含私人内容，需要保护。恢复前先确认当前远端变化，不要直接强推旧镜像。
