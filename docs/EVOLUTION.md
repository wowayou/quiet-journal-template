# 核心与个人内容分层、内容工具升级方案

发行范围：**2026-10-25 包含 A0/A1/B1/B2、本地复验后的三项状态修复，以及发布说明和手动本地兜底。可选 Newsletter 表单已接入但默认关闭；评论与真实订阅账号未开通**。本文件保留设计目标与分片验收；各实例是否已部署必须核对对应固定提交、构建结果和实际网站，不把代码接入等同云端开通。

## 已落地的文件边界

- 核心后台字段：`assets/admin/schema.yml`；实例连接：`data/editor.yaml`，扩展可新增 `data/editor_extensions.yaml`。Hugo 直接生成 `/admin/config.yml`（JSON 是 YAML 子集），不保留静态副本。
- Hugo 使用原生配置分片：实例 `hugo.toml` + `params.toml`；核心 `frontmatter/markup/cascade/permalinks/module/outputs/pagination.toml`。试验确认任意 `hugo.instance.toml` 不适合本版本多语言加载，未采用该方案；不引入需要额外生成器的双份配置。
- 文件归属与三方升级预览：`scripts/core-upgrade.mjs` 和固定 `core-manifest.json`。本轮只实现只读升级预览，不自动应用/删除、Git 或远程任务；个人挂件声明/全局钩子、环境配置和私密服务输入排除，新核心占用其路径时标记受保护。完整薄实例依赖分发仍是后续设计。
- 图形工具真实实现见 [TRANSFER.md](TRANSFER.md)：ZIP/目录、自动检查、摘要/分页/文字差异、哈希绑定确认、任务/取消/刷新恢复、完整报告及原生下载。
- 邮件表单配置在 `data/newsletter.yaml`，默认关闭。已实现文末原生 POST、页脚链接及按文章精确 CSP；账号核价、真订阅/退订和真实邮件尚未执行。评论不发邮件的独立约定保持不变。

### “分离”的实际保证与缺口

这里的“已落地”指**代码实现与本地验收**，不代表已有站点自动升级。2026-10-25 最初的发布前核查发现：分层版本尚未进入正式远端与线上。后续是否已交付仍须按实例核对实际提交和部署，不能只据本地清单或测试判断。

已实现的是**文件所有权和升级保护**：内容、日常设置、实例连接与核心设计代码有明确边界，核心升级不应覆盖个人输入。尚未实现的是**独立发布与构建故障隔离**：文章、设置和模板仍通过同一次 Hugo 整站构建；即使文件分开，核心与合法设置不兼容仍会阻止整站新版本上线。固定核心分发还处于清单/只读预览阶段，并不是已交付的薄实例依赖或独立内容流水线。

旧版自定义图标曾出现“后台 image 字段允许保存 HTTPS 地址、渲染器却拒绝”的契约不一致；不能把这种正常设置引发的失败归咎于作者。修复需要同一发行中的后台、渲染与检查规则一致，并实际上线。升级验收必须在私密隔离候选中使用**待发布核心 + 最新远端个人输入**，核对设置/文章/图片及有效配置，再确认真实部署；仅文件归属或合成测试通过，不能代替这个交付闭环。安全性非法输入仍应明确拒绝，不以发布便利为由放宽草稿/媒体保护。

## 2. 分层：公开核心，私有薄实例

目标：**升级功能不覆盖个人内容；后台保存个人设置不修改核心；两个仓库不强行合并历史。** 私人文章和个性化设置仍在同一个私有仓库，日常写作与现有文章地址保持不变。

| 所有者 | 范围 | 规则 |
|---|---|---|
| 用户内容 | `content/**`、`assets/media/**`、日常 `data/*.yaml` | 核心更新永不覆盖或删除；结构变化需要显式迁移 |
| 用户定制 | `assets/css/overrides.css`、可选 custom.js、已声明的扩展与布局覆盖 | 从受管核心之外加载；不因为“不是上游文件”就删除 |
| 实例运维 | 站点 URL、CMS 仓库/分支/工作流、Worker/域名、评论与订阅接入选择 | 保存在私有实例中，不能从模板示例覆盖 |
| 核心代码 | 共享布局/样式/脚本、后台字段定义、检查器与安全默认值 | 按固定发行版本维护，精确比较后更新 |
| 生成文件 | 后台最终配置、构建产物 | 可重建、禁止手工维护，不与输入形成两份真相 |
| 密钥与外部数据 | CMS 令牌、数据库/JWT、评论库、订阅者名单 | 不进公开模板、静态产物或普通内容包；独立存储和备份 |

### 第一片只拆混合配置，不搬所有文章

- `static/admin/config.yml` 拆成核心字段定义与实例编辑器配置；由**确定性的构建步骤**组合生成，保留实例 repo/分支/工作流和明确声明的扩展字段。生成器拒绝未知字段及冲突，不拼接任意 YAML 片段，也不动态读取 CMS 的内部 DOM。
- Hugo 的 `baseURL`、时区和媒体选择与共享默认值分层；构建后检查最终有效配置，防止实例覆盖意外打开草稿/未来文章、自动发布原图或任意 HTML。
- `wrangler.jsonc` 暂保留为实例所有，不为形式统一再生成一套部署配置。共享安全约束由检查器验证；生成配置仅应用在确实存在混合归属的地方。
- 个人 CSS、扩展与页面 ID 不改，现有 CMS 路径与 `/posts/<id>/` 不迁移。直接运行 Hugo、开发预览、CMS test-repo 和生产构建都必须拿到同一份有效字段定义；不能只修生产命令。
- 不引入新的 GitHub Actions、自动同步机器人或部署触发器。仍沿用既有构建，配置生成只能包含本地必要工作，不联网拉取最新版本。

### 核心分发：先固定版本，再考虑依赖形态

**推荐近期用固定发行快照 + 受管文件清单，不立即同时引入 Hugo Module、npm 主题包和 Git 子模块。** Hugo Module（Hugo 的版本化模块机制）能管理主题，但不能独自管理 Node 检查器、内容工具与 CMS 生成器；现在拆成两套同步版本会增加维护面。

第一片加入核心版本/文件归属清单（含代码维护的 `data/widget_types.yaml`，其余 data 内容保持实例所有）；升级流程使用“旧核心基线、实例当前文件、新核心版本”三方比较：

- 当前文件仍等于旧基线：允许预览更新；与旧基线不同：报告本地定制冲突，不自动覆盖。
- 新版本删除文件：只有确认为核心所有、且实例未修改时才可列入删除计划。
- 更新开始前后核对源哈希和个人文件哈希；并发 CMS 改动导致停止重做比较，不靠重置解决。
- 先生成升级报告，再在干净分支或隔离目录应用；升级不自动提交、推送或部署。
- 锁定发行提交/归档哈希，不跟随 `main` 或 `latest`。主题模块或单一核心包的可行性等边界稳定后再做小实验，不把实验当现成发布路径。

这样短期仍保留核心文件副本，但日常不再人工判断“这次能复制哪些文件”，也不需要一次性迁移所有目录。真正薄化实例是后续选择，不应伪装为当前已完成。

## 3. 内容工具 V2：以任务为中心，而非命令说明页

### 3.1 两个入口

- **导出内容**：本地内容摘要 → 确认范围及私人内容 → 生成并取走内容包。
- **导入内容**：选择内容包 → 自动检查并比较 → 明确确认 → 恢复到新的隔离目录。

不把导出和导入画成必须依次完成的“1、2、3”；读者只是备份时无需理解另一半流程。

### 3.2 导出

- 默认保留全部本地文章和图片，明确包含草稿/未来内容/未引用资源。可单独决定是否包含站名、导航、友链等内容设置；不默认做“公开分享包”，避免误判私密状态。
- 用文章、普通页面、图片/图标、设置与体积说明范围；日期与草稿解析失败就提示，不猜测数量或静默漏掉文件。
- 显示本地仓库及同步边界；可只读显示本地 Git 状态，但**不自动 fetch/pull**。不知道远端是否最新时明确说不知道。
- 输出增加 **ZIP 内容包**（普通压缩文件，含原来的清单和文件），目录格式继续支持；不伪造专有格式，不把压缩当加密。
- 完成态显示完整路径、可复制路径、下载/取走包与简短摘要。打开目录如实现，限已生成且确认的路径、禁止 shell 拼接；不启动任意命令。默认先实现复制/下载即可。

### 3.3 导入与比较

- 支持原生选择按钮和拖放 ZIP；旧版目录包继续可选。不要求用户先把文件搬到工具规定的目录。文件选择器不能凭空赋予后台任意磁盘权限；文件上传只进入本机服务的临时私密区，并清楚标注“仅本机处理”。
- 选择后自动完成格式、完整性、路径及媒体检查，展示真实阶段，不追加一个容易漏点的“检查”按钮。
- 默认看“需要关注”：新增和内容不同；可切换全部/冲突、搜索路径、分页。内容不同不是损坏，必须与无效路径/坏媒体区分。
- Markdown/YAML 提供按需、只读、转义后的文字差异；图片用安全预览或尺寸/哈希说明，不执行包内 HTML、JS、shortcode。未知元数据只展示，不自动导入账号或密钥。
- 完整报告可下载，不强迫为第 101 条返回终端；展示分页不代表截断包内文件。
- 导入完成保留比较结果，突出“**已恢复到新目录，当前博客没变**”。合并与发布不在此动作里；同名文件和设置由用户另行决定。

### 3.4 先修安全与状态，再添加便利

- **确认绑定快照**：检查后返回包含源文件清单/内容哈希、目标比较指纹的 review ID；执行前复核。任一变化都要求重新预览。仅验证包当前“有效”不能替代验证“与已确认相同”。
- **任务有身份**：一个本机服务同一时间只执行一个内容操作；重复点击/请求用 operation ID 返回原任务，不新建第二份。状态为等待、检查、复制/打包、完成、失败、取消；无伪进度。
- **主页面不被阻塞**：大包处理放到一个受限工作线程或子进程，主服务可查询状态；不无限排队/并行。浏览器只在任务进行时有界查询，页面关闭后不新增请求、不自动重发写入。
- **刷新可恢复**：独立会话可保存在当前 tab 的 sessionStorage（会话存储），与 CMS 存储隔离；不放进持久 localStorage、日志、查询字符串。主服务重启/会话失效时明确重新连接。需要重新评估同源页面和关闭 tab 后的边界，不能声称能防御本机恶意程序。
- **ZIP 与解包防线**：保留总文件/单文件/总量限额，另外限制压缩输入、解压实际字节、压缩比和时长；拒绝路径穿越、大小写/Unicode 冲突、符号链接、设备文件、重复记录、加密/嵌套压缩包及不支持的压缩方法。不能先不受限解压再校验。
- 选择固定且维护中的 ZIP 库、核对依赖/许可并测试；不手写通用解包器，不用 `unzip`/shell 直接接受用户路径。若暂不能可靠满足限额，先交付目录向导，ZIP 明确标待办，不做不安全降级。
- 原文件与目录不覆盖；最终清单/报告作为完成标志，失败/取消只清理本次临时输出。超时不等于没写入，先查询任务状态；不得悄悄继续或重发。

### 3.5 视觉与文案

- 细边框、单一强调色、清楚的标题/摘要/主按钮；深浅色与现有博客一致，不新增主题系统或动画依赖。
- 私人内容提醒靠近最终动作，仅讲关键风险；解释、限额、命令行方式折叠在“了解更多”。减少免责声明的重复，但不隐去草稿包含与不自动发布。
- 空态告诉用户要准备什么；错误包含“哪个文件、为什么、怎么处理”，缺少权限与损坏包不能都写“未完成”。
- 键盘和触控等价；至少 44px 操作区域，焦点随阶段有明确去向，读屏状态播报不重复整张文件表。
- 保留命令行接口和旧内容包格式兼容测试，GUI（图形界面）只是同一引擎的另一入口。

### Newsletter：Buttondown 仅作为可选投递层
