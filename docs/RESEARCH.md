## 参考站点：借方法，不照搬复杂度

### AstroPaper 的 “Mingalaba” 首页

来源：[首页](https://astro-paper.pages.dev/)、[RSS](https://astro-paper.pages.dev/rss.xml)、[源码项目](https://github.com/satnaing/astro-paper)。Mingalaba 是演示站问候语，不是 RSS 服务名。

值得借鉴的是：简短自我介绍、精选与最近文章分开、订阅/社交入口可找到、图标在交互时有轻量反馈，而不是给整页添加持续动画。本站保留单栏和现有视觉语言，本轮补全图标导航、同源搜索、可替换分享图与动效变量。不复制其代码、文案或样式文件，也不沿用其演示账号。

RSS 路径由各自生成器决定：AstroPaper 是 `/rss.xml`，本模板 Hugo 是 `/index.xml`。参考站的订阅链接不能当成自己站点的订阅源。

### snarfed.org/about

来源：[About](https://snarfed.org/about)。页面直接说明作者是谁，列出身份/联系入口；保留 2002 年的首次发布时间与 2025 年更新时间，叙述域名长期使用、托管与软件迁移的历程，并说明内容许可。它的辨识度主要来自**具体的人、长期维护和稳定身份**，而不是复杂装饰。

本轮采纳：社交身份链接、明确的作者归属、真实发布/更新时间、内容与模板独立、长期稳定的页面 ID。页面提到 WordPress 和历史插件不等于这些基础设施也适合本模板；不因参考它就增加 WordPress、联邦收件箱、评论或统计服务。

### Shopify 富文本编辑器

来源：[官方帮助](https://help.shopify.com/en/manual/shopify-admin/productivity-tools/rich-text-editor)、[Sveltia RichText](https://sveltiacms.app/en/docs/fields/richtext)。

借鉴“明确的链接文字/地址/打开方式”和统一标题、表格、图注操作。Shopify 同时允许 HTML、媒体嵌入和更自由的排版，但这些会带来复制粘贴格式污染、跨域请求与维护分支。本站保持 Markdown，使用有界的链接组件提供单条打开方式，不改造或 fork 整个编辑器。

## 2026-10-16 新增的阅读页与首页参考

本轮读取三个实际 URL 的 HTML/CSS，并在本机 Chromium 以 1280/390px 观察静态布局。浏览器禁用 JavaScript，仅作只读观察，没有登录、订阅、留言或点击跟踪；不能据此宣称其动画、真实交互、转化率或全部移动设备已验收。本项目的主要目标是让读者理解作者并开始阅读，流量来源/转化数据未知，不为个人博客硬套销售漏斗。

### Asher：文字节奏与继续阅读

来源：[How to Build Wealth as a Career Person](https://asheradeniyi.com/2026/04/10/how-to-build-wealth-as-a-career-person/)。所见桌面以文章为主、右侧 More Posts 为辅，标题和真实日期清楚，正文段落留白较大；本次正文区约 612px、20px 字/32px 行高，手机约 342px 宽，无横向溢出。

可借鉴**段落节奏、文章元信息与轻量的继续阅读入口**，不照搬整页灰底、英文断词规则或 WordPress 组件。Quiet Journal 已有上下篇导航；是否再加作者精选内链，应看内容量，不为了模仿就加永久侧栏、分享插件、通知邮件或另一套评论系统。

### Anton：尽快进入正文，读完仍有去处

来源：[Write the damn code](https://antonz.org/write-code/)。实际页面是简洁站头、大标题、单列正文，引用/列表/粗体承担层级；订阅、日期、上下篇和 See also 位于文章尾部，避免把所有动作堆到开头。

可借鉴**正文优先和文末少量人工推荐**。其搜索表单会转到 DuckDuckGo，页面包含统计脚本；不因此替换本站同源搜索或引入统计。人工推荐先用现有 Markdown 内链，不假装已有自动相关推荐。中文的字宽、字重和行高仍需本地内容验证，不能直接套英文数字。

### Abo：欢迎页的画面感，而非强制入场门槛

来源：[欢迎页](https://blog.abohack.com/)。桌面是低饱和插画与大标题居左、短说明和“进入博客”按钮居右，薄分隔线、纸面感和大量留白形成明确层级；手机改为上下排列。它是 `/` 欢迎页，实际文章列表另在 `/blog/`。

可以借鉴**主次分栏、少量介绍、单一明确入口及克制配色**，但应使用作者自己的文字与有权使用的图片，而不是直接复制该站插画、标识、文案或主题代码。页面源码还含统计、giscus 预连接与入场等待动画，这些与本项目现有隐私/轻量边界不同，不照搬。

本次更新采用“欢迎区 + 同页开始阅读”，不让熟悉的读者每次先多点一次或等待开门动画。旧单栏方案不是永久禁令；若作者以后确定采用独立欢迎页，再单独设计首页/列表迁移。本次保留文章 URL、归档、搜索与 RSS，不改路由或覆盖个人介绍。

### Linexic：把个人表达与技术信息分开

来源：[Linexic](https://www.linexic.top/)。实际页脚把版权年份/站名、技术与主题回链、个人宣言、运行时间和 RSS/Sitemap/个人主页分层放置；页面明确标注 Based on Koi。借鉴的是**可辨识的个人语气和清楚的分组**，不是别人的具体文案与建站日期。

现有 `footer.quote`、`content_license`、回链开关与社交/RSS 已覆盖大部分文字定制，不需换框架或允许任意 HTML。[CUSTOMIZE.md](CUSTOMIZE.md#页脚文字与个人表达) 已补配置示例。参考站的秒级计时包含内联脚本和字符串形式的 `setTimeout`，不能直接粘贴进本项目；只有确需该行为、确认真实起始时间并另行测试后再实现，不能凭“看起来可爱”增加每秒更新或放宽 CSP。本次更新只重新分组，未改作者现有页脚文字或开关。

### Koi：配置与组件分离，而非迁移技术栈

来源：[tcdw/koi](https://github.com/tcdw/koi)。本次核对 README、实际 LICENSE、包清单及 `87c7d4fa39ae6af7e552584007a2797b2b8e0c45` 的页脚/内容配置。原页脚通过常量读取站名与起始年，其他自定义应与固定结构分开；这个职责划分适合参考。其 Astro/Tailwind/Svelte 技术栈不需要为了页脚或首页观感迁入 Hugo。

实际许可是 **MIT，版权为 tcdw**，不是从 GitHub 标签推测；若未来确实复制代码，必须保留相应版权/许可并更新本站来源说明。作者另外在 README 希望保留 Based on Koi 字样，应与 MIT 正式条款区分，并在真实采用时尊重这一署名请求。仅做独立实现的设计参考，不冒称本站使用了 Koi，也不把其演示图片默认视为可随意使用。README 亦提醒横幅图会影响标题对比度，视觉参考不能替代深浅色/键盘/手机验收。

**首页欢迎区与页脚已按上述取舍独立实现，作者已于 2026-10-19 确认样式验收，随本次更新交付。** 欢迎区使用原创静态线描和现有文案，桌面分栏、手机堆叠；页脚只重排已有设置。Asher / Anton 的阅读页建议仍是参考，本次不改文章正文排版或增加推荐组件。现行结构见 [DESIGN.md](DESIGN.md)，配置见 [CUSTOMIZE.md](CUSTOMIZE.md)。这些站点/主题的文章、图片与运行代码未复制进模板；本地抓取和验收截图不作为模板分发素材。

## 额外三个优化项（尚未实施）

| 优先级 | 优化项 | 为什么值得做 | 最小实现 / 成本与验收 |
|---|---|---|---|
| **1** | **“从这里开始”阅读地图 + Now（近况）页** | 新读者不一定想从最新一篇开始；几条亲自挑选的路线和真实近况，比模板化的长简介更能形成作者气质。借鉴 snarfed 的长期身份叙事 | 直接用已有 `layout: page`、稳定 ID、Markdown 内链和精选；不加 JS 或服务。只放 3–5 个真实入口，近况变化时手工更新，宁可少而真。验收：手机两次点击内到代表作、无坏链接，不把长期不更新的状态冒充实时状态 |
| **2** | **照片联系表（可选照片索引页）** | 首页保持文字节奏，同时给喜欢照片的人一条视觉阅读路线；不是再做一套首页皮肤 | 新页面布局复用 `media.html` 的重编码/懒加载与现有放大组件；只选公开图文，缩略图尺寸固定，图注由作者写。不读 EXIF、不远程拉取、不自动生成地点。建议首批最多 24 张，再按需分页；验收手机首屏不拉全部大图、尺寸不跳、草稿与未选图不泄漏 |
| **3** | **长文的章节直链与脚注回跳** | 读者能精确保存/分享一段内容，也便于作者有根据地写作；比滚动进度条或固定侧栏更实用 | 现有可折叠目录保留，增加轻量标题锚点入口、脚注返回焦点；优先 Hugo 原生 Markdown，无服务、无滚动监听。若以后提供复制链接按钮再按需加极小脚本。验收中文/重复标题、键盘、移动端、旧锚点与无 JS；不自动改已发布的标题 ID |

这些收益是产品判断，不是流量提升承诺。建议先做第 1 项，甚至只写内容即可；第 2/3 项等真实照片量或长文需求出现后再决定，**本轮不自动展开实现**。

## 已落实的成本与边界选择

- 搜索用构建期 JSON + 本地浏览器匹配，不引入 Algolia/搜索服务器；默认不下载索引，关键词不上报，原始索引硬上限 2 MiB。
- OG（Open Graph，分享卡片）使用 Hugo 构建期生成；中文字体只放构建端，不添加在线生成 API、Worker 或浏览器字体下载。上传封面仍优先。
- 社交身份按 [Mastodon 官方规范](https://docs.joinmastodon.org/user/profile/)做 `rel=me` 与 `fediverse:creator`，不混称为完整联邦发布。官方标准资料栏 4 行，每个网站分别验证；实际字段上限与作者归属支持取决于实例。
- Cloudflare [Workers Builds 限额与计费](https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/)仍按账户共享用量，见 [DEPLOY.md](DEPLOY.md)。本轮没有改触发器、预览分支、重试策略或套餐；本地多跑检查不会变成云端构建任务，生产保存/推送仍会消耗既有构建额度。
- 不新增针对参考站/社交站的定期爬取、远程可用性探测或自动发帖。今后任何这类功能都必须单独核对服务条款、权限、频率、预算和失败处理。
