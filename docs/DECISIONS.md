# 取舍记录（v1.0 定稿）

判断方法：一项功能值得做，要满足「降低记录阻力或保护隐私的收益 > 开发 + 长期维护 + 每次使用时多出来的选择」。已经写好的代码是沉没成本，不作为保留理由；删掉的东西都能从 Git 历史找回。

## 一定不做

| 事项 | 理由 |
|---|---|
| 自建 CMS / 后端 / 数据库（D1、KV） | Git 已经提供了存储、版本、备份、导出；再加一层只增加运维和故障点 |
| 自建登录系统、OAuth 服务 | 单人使用，细粒度令牌已够；OAuth 需要多部署一个服务，令牌最终仍存浏览器，安全收益很小 |
| GitHub Actions 构建 | 免费分钟数已用完；Cloudflare Workers Builds 免费且已接通 |
| 第二个 GitHub 账号 | 违反 GitHub 条款，且解决不了任何实际问题 |
| 评论、点赞、浏览量、统计、广告 | 与「安静记录」相反；会引入第三方脚本，破坏 CSP 对登录令牌的保护 |
| 标签、分类、系列 | 心智负担大于检索收益；按时间归档 + 浏览器搜索已够 |
| 多语言 | 只有一个作者、一种语言 |
| 视频、GIF | 体积、元数据、播放器维护成本高；`check-media` 直接拒绝 |
| 自动 AI 改写、写作打卡、热力图 | 把记录变成任务 |
| 每篇文章的「排版选项」 | 每多一个选项，写作时就多一次犹豫 |

## 做成可选（默认关闭或默认值）

| 事项 | 默认 | 理由 |
|---|---|---|
| CMS 审核流（Editorial Workflow） | 关（simple） | 单人写作不需要审核，且每次保存多 5 次请求；但「草稿完全不进 main」对部分人有价值，切换只需改两行配置 |
| 强调色 | 橙 | 只换一个颜色变量，不增加版式分支；5 种都已检查对比度 |

## 这一版删掉的（曾实现过）

| 事项 | 理由 |
|---|---|
| 多套风格预设（雾、夜、文楷）与霞鹜文楷字体（4.7 MB） | 选定了一种风格；多套风格让每次修改都要测四遍 |
| 首页卡片布局、按年分组时间流 | 与选定的列表风格重复 |
| 图片轮播 | 把照片藏在滑动后面；手机上同段并排 + 点开放大更直接 |
| 滚动渐显动画 | 纯装饰，参考的 AstroPaper 也没有 |
| 固定在侧边的目录、目录滚动高亮 | 生活记录很少有长文；保留可折叠的简单目录 |
| 页头 / 页脚的多种布局与导航样式 | 已定稿：A 的页头 + B 的页脚 |
| 首页缩略图条、类型标签、字数 | 打乱文字列表的节奏 |
| 头像 | 首页大标题已承担「这是谁的地方」 |

## 暂不做，等出现真实需要再评估

| 事项 | 触发条件 |
|---|---|
| 站内搜索 | 文章超过约 200 篇，且归档页找不到东西 |
| 图片存到 R2 | 仓库超过约 1 GB，或 Git 操作明显变慢（接口已预留，见 R2_FUTURE.md） |
| 换编辑器 | Sveltia 停止维护，或手机上持续出错（接口见 EDITING.md） |
| CMS 自托管（不从 unpkg 加载） | unpkg 不可用或出现供应链事件 |
