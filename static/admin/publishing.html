保存了，网站还没更新？

保存到仓库不等于网站已上线。 已成功提交到 GitHub 的文章和图片，不会因为部署失败而消失。未保存的输入不能据此保证恢复。

正常流程：后台保存 → GitHub 提交 → Cloudflare Workers Builds 构建并部署 → 网站更新。这个页面不读取云端状态。后台顶部的网站状态会显示网站当前版本的生成时间，以及被跳过的设置；如果时间早于你最后一次保存，说明新版本还没上线。

先确认内容，再看构建

  1. 在自己的私有 GitHub 仓库确认文章和图片已提交；检查草稿开关和带时区的发布时间。草稿或未来文章不会公开。
  2. 在 Cloudflare 控制台打开本站 Worker → Builds，找到对应提交，查看构建和部署日志。GitHub 的提交检查也可看到成功或失败及详情入口。
  3. 失败时，线上通常保留上一次成功版本。先修复错误，不要反复保存、重发、删除文章或回滚整个仓库来“催发布”。删除或撤下同样需要部署成功才会在当前网站生效。

云构建额度不足时

可以继续写作和保存到 GitHub；只是新版本可能无法上线。本站默认不用 GitHub Actions，应先确认耗尽的是哪种额度。Cloudflare 的账户状态、静态资源限制或权限问题，不能靠本地构建绕过。

请维护者先核对 Workers 套餐、账户共享用量及当前官方规则，再暂停该 Worker 的自动构建。在电脑上使用远端最新 main 的独立干净克隆，安装锁定依赖后运行：

npm run publish:fallback -- --check

这会核对远端最新提交并运行完整生产构建，不会发布。工作区未提交、落后于远端、草稿/媒体/链接等检查失败时会停止，不自动合并或绕过错误。旧版本仓库没有此命令时，先按仓库更新说明审查升级。

检查通过后，由维护者按仓库 docs/DEPLOY.md 显式确认提交、Worker 与账户再手动发布到原站点。它只绕过云端构建，不自动换平台、开通付费能力、群发邮件或创建定时任务。不要把 Cloudflare 令牌填到写作后台。

发布失败、超时或断线后，先检查 Cloudflare Deployments 中的实际版本，不要立即重试。恢复自动构建前确认远端代码和最新手动发布版本一致，避免旧内容重新覆盖。
